# Qoder 签到

> 每天自动领取 Qoder CN「每天领 100 Credits」，GitHub Actions 云端运行，不需要开电脑。

## 这个仓库是什么

Qoder 的每日签到，靠 GitHub 的定时任务跑，本机不用常开。

- 私有仓库：不出现在公开搜索里，降低被扫号/风控的概率
- 纯标准库，零第三方依赖
- 凭据存在 Secrets，不进代码、不进日志
- 失败自动推企业微信（只推失败，成功不打扰）

## 领取窗口

Qoder 的活动窗口是 **今天 10:00 → 明天 10:00**（UTC+8）。

| 北京时刻 | 作用 |
|---|---|
| 07:00 | 主班。GitHub cron 常延迟 3~7.5 小时，落点大概率在 10:00 之后，届时直接领取 |
| 10:05~15:35 | 状态巡检，每 15 分钟一次（只读，不直接领取） |

两个账号之间固定间隔 5 分钟（主账号先领，第二个号等 300 秒）。

## 状态巡检与自动补跑

不挂固定补签班 —— 固定班可能和延迟落地的 7 点主班撞车，触发上游风控。
改为 `watchdog.py` 只读巡检，按「当前状态」决定要不要补跑：

1. 查今天主 workflow 的 schedule run：
   - 没有 run → 主班还在 GitHub 调度延迟里（run 尚未创建），静默等下一轮
   - 有 `queued` / `in_progress` → 已落地还没跑完，静默等下一轮
   - 全部 `completed` → 才看结果
2. 有「10:00 之后开跑且成功」的 run → 判定已领到，静默收工
3. 否则 → 需要补跑；**15:00 之后不再等排队**，直接进入补跑判断
   （实测最长延迟 7.5 小时，15:00 主班怎么都该跑完了）
4. 补跑 = dispatch 主 workflow（幂等 + `concurrency` 串行 + 5 分钟账号间隔），
   **巡检绝不自己发 claim**；补跑前查今天 10:00 后是否已有 dispatch run，避免重复触发

推送语义：排队中 / 已领到 / 窗口未开 → 静默不推；补跑成功推 ✅、失败或超时推 ⚠️。
窗口未开时连积分播报也整条跳过，避免早上收到一条「积分没变」的无效消息。
「有可领活动却一个都没领到」现在改判为失败，会推 ⚠️ 并让 Actions 变红。

演练：手动 Run `qoder-watchdog.yml`，勾选 `dry_run`，只诊断不触发补跑。

## 怎么部署 / 怎么维护

本机工具在 `D:\GITHUB签到\QODER签到更新\`，只有一个入口：

1. 在 AI路由魔改版 里登录 Qoder 账号
2. 双击 `一键更新.bat`
   - 读 AI路由魔改版 里的全部 Qoder 账号，依次上传凭据
   - 第 1 个 → 仓库级 Secret；其余 → 各建 Environment `qoder-<编号>`
   - 代码与 workflow 逐字比对，一致就跳过，有改动才上传
   - 触发一次云端自检

首次部署和日常维护都是它 —— 缺什么补什么，幂等。

## 每日积分播报

每天签到完成后，`daily_report` job 汇总全部账号，推一条消息到手机。每个号只三行，
不展开账本细节（2026-11-19 按使用需求简化）：

```text
【Qoder · 每日积分播报】2026-11-19

本次收到 4 个账号的积分数据

1. 尾号 6717
   当前积分：701 分
   1 分于 2026-11-27 到期（剩 8 天）；建议 2026-11-26 前用掉，提前一天
   700 分约 2026-12-13 开始每天到期 100 分
```

⚠️ **两条独立的到期线**（2026-11-19 修正；之前把两者合在一个日期上是错的）：

| 积分类型 | 到期规则 |
|---|---|
| 套餐额度（`userQuota`） | 随 `expiresAt` 本周期整批到期 / 刷新 |
| 签到资源包（`addOnQuota` 等） | 每笔领取自领取之日起 **30 天**内有效，**各自滚动到期**（官方《每日领取 100 Credits》规则） |

所以「每天签到」不会「同一天过期」：每天领 100 分，就是每天有 100 分到期。
之前的播报把「套餐剩余 + 资源包剩余」合计挂在本周期到期日上（如「701 分 11-27 到期」），
其中 700 分资源包根本不在那天过期 —— 已改成两条线分别显示。

**资源包「约 X 到期」会自动跟着消耗往后推**（不用手工记账）：

- 上游 `addOnQuota` 直接给 `total / used / remaining`，消耗了多少不靠猜；
- 剩余笔数 = `ceil(remaining/100)`；最早到期日 = 最后一笔到期日 −（笔数−1）天；
- 例：700 分（7 笔）今天领 → 「约 12-13 开始每天到期 100 分」；用掉 300 分剩 400（4 笔）
  → 「约 12-16 开始每天到期 100 分」。剩余不是整百时首日不满 100（如剩 350 分
  → 「约 12-16 开始到期 50 分，之后每天 100 分」）；
- 最后一笔日期优先取账本（`ledger/claims.json`）；账本还没覆盖时看**当天签到结果**：
  `claimed` / `done`（今天领到）= 今天+30；`failed` / `ineligible`（今天没领到）= 今天+29。
  **不默认今天签到成功**——宁可把到期日算早，绝不把已到期的积分算成还没到期。
- 已过期的积分不再出现在播报里。

- 数据来源：云端只读调 `/sash/api/v2/me/usage`，与 AI路由魔改版 本地余额口径一致；
  查不到只标注「未取到」，不影响签到结果与心跳。
- 推送凭据：`WECOM_APP`，由「一键更新」从 参数配置\配置.json 的 `wecom` 自动写入 Secret。
- 关闭：仓库 Variable `RECOMMEND_NOTIFY=0`。

## 领取账本（`ledger/claims.json`）

官方接口只给「总积分 + 本周期到期日」，**没有逐笔明细**（已实测：credits / transactions /
usage history 等端点全部 404；网页端明细要 Cookie 登录态，Actions 拿不到）。

但签到这一步是我们自己的确定信息：每笔 100 分、领取后 30 天有效。
所以每次**真领到**时记一笔（只记领到的，失败/已领不记）：

```json
{ "uid": "...", "account": "尾号 6717", "credit": 100,
  "claimedAt": "2026-11-19T11:54:52+08:00", "validDays": 30, "expireAt": "2026-12-19" }
```

- `merge_ledger.py` 在播报 job 里合并各账号 artifact，按「uid + 领取日期」去重
  （补跑 / 重跑不会重复记账），由 workflow 提交回仓库（只给该 job `contents: write`）。
- 从启用当天开始精确；之前的历史按「资源包剩余 ÷ 100 + 连续领取」倒推，
  误差按天计，播报统一用「约」表述（不显示笔数、估算来源这类细节）。
- 本地 AiRoute 按日记录总积分快照，与这本账对账，就能算出每天领取/消耗与逐笔剩余。

## 环境变量（Actions 自动注入 / Secrets）

| 名称 | 说明 |
|---|---|
| `QODER_ACCESS_TOKEN` | `dt-` 访问令牌 |
| `QODER_REFRESH_TOKEN` | `drt-` 续期令牌，可自动续期 |
| `QODER_UID` | 账号 uid |
| `QODER_MACHINE_ID` | 设备标识（续期用） |
| `WECOM_APP` | 企业微信应用凭据 `corpid,corpsecret,touser,agentid` |
| `GITHUB_TOKEN` | Actions 自动注入；巡检用它查 run 状态、dispatch 主 workflow |

## 多账号

仓库变量 `QODER_ACCOUNTS` 列出账号编号（逗号分隔），每个编号对应一个
Environment `qoder-<编号>`，环境级 Secret 覆盖仓库级同名值，互不干扰。

⚠️ 官方限制：Qoder 按「人」去重，同一台机器/同一个人名下多个账号，
当天只有第一个能领到，其余返回 `SAME_PERSON_ALREADY_CLAIMED`。

两个账号之间固定间隔 5 分钟：主账号先领，动态账号靠 workflow 里的
`needs: checkin_main` 排在主账号之后、再等 `sleep 300` 才发 claim。

## 排错

| 日志 | 含义 |
|---|---|
| `当前北京时间 XX:XX，今天 10:00 的新一轮还没开放` | 7 点主班没延迟、窗口未开；不算失败也不推手机，巡检 10:05 起接手 |
| `没有领到（可领活动均未成功）` | 真失败：Actions 变红、推 ⚠️，巡检会补跑 |
| `今天已领过` | 已领到，正常 |
| `鉴权失败（HTTP 401）` | 令牌过期，回 AI路由魔改版 重登后跑「一键更新」 |
| `同一人今天已领过` | 官方去重，不是故障 |
